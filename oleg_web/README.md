# oleg_web — веб-интерфейс реестра обязательств

Одна страница, на которой видно весь реестр, можно прогнать движок по пачке
входящих и посмотреть, что изменилось. FastAPI + vanilla JS, без сборки,
без внешних CDN.

## Запуск

```bash
cd <корень worktree>          # там, где лежит папка oleg_web/
python -m oleg_web                                       # http://127.0.0.1:8765
python -m oleg_web --port 8765                           # другой порт
python -m oleg_web --features timeline,edit,run_examples # включить надстройки
```

Открыть в браузере `http://127.0.0.1:8765`. Сервер слушает только петлевой
адрес и не требует аутентификации — это инструмент для локального демо.

## Что делает каждый элемент управления

| Элемент | Что делает |
|---|---|
| **Входящие** (список) | Папки `input/`, найденные автоматически в `examples/*` и `examples_test/*`. |
| **…или свой путь** | Произвольная папка со входящими; перекрывает список. |
| **Перетащить файлы** | Кладёт файлы во временную папку `out/uploads/<метка>` и подставляет её путь. |
| **режим** | `авто` — как решит движок; `параллельно` / `последовательно` передаются движку как `--mode`. |
| **новый реестр / поверх текущего** | «Новый» удаляет `registry.json` и `registry.md` перед прогоном; «поверх» оставляет их, и движок сливает результат в существующий реестр. |
| **Прогнать ▶** | Запускает движок подпроцессом, стримит его stdout в лог, потом перечитывает реестр и показывает `создано / обновлено / закрыто`. Горячая клавиша: `Ctrl+Enter`. |
| **Обновить** | Перечитывает `registry.json` с диска, ничего не запуская. |
| **Прогнать примеры** | Запускает пайплайн по выбранной папке примеров и вытаскивает из вывода строку `прошло N из M`. За флагом `run_examples`. |
| **Заголовки таблицы** | Клик — сортировка по столбцу, повторный клик — обратный порядок. Закрытые записи всегда внизу и затемнены. |
| **Имя файла-источника** | Открывает исходный файл и показывает, найдена ли цитата в нём дословно (`✓` / `✗`). |
| **Треугольник слева** | Раскрывает таймлайн записи. За флагом `timeline`. |
| **Поля владелец / срок / статус** | Правятся прямо в таблице; кнопка **Сохранить правки** (`Ctrl+S`) пишет файл. За флагом `edit`. |

## FEATURES — надстройки и их значения по умолчанию

Единственное место включения — словарь `FEATURES` в `oleg_web/server.py`.
Ядро (страница, таблица, прогон движка, просмотр источника) не зависит
ни от одного флага и работает всегда.

| Флаг | Что даёт | По умолчанию в коде |
|---|---|---|
| `timeline` | Раскрытие строки: история изменений по порядку, что чем заменено, все источники с цитатами, диф последнего прогона. | `False` |
| `edit` | Inline-правка владельца, срока и статуса + `POST /api/save`. | `False` |
| `run_examples` | Кнопка «Прогнать примеры» + `POST /api/run_examples`. | `False` |

Значения по умолчанию — выключено, пока флаг не пройдёт свой собственный
тест; тогда он переводится в `True` одной правкой в этом словаре.

Три способа переопределить, по возрастанию приоритета:

1. переменная окружения `OLEG_WEB_FEATURES="timeline,edit"`;
2. флаг запуска `--features timeline,edit`;
3. query-параметр страницы или запроса: `?features=timeline,edit`.

Синтаксис одинаковый: список через запятую, префикс `-` выключает
(`?features=-edit`), слово `all` трогает все сразу (`?features=all,-edit`).
Query-параметр применяется и к API: `POST /api/save?features=edit`.
Без флага защищённые ручки отвечают `403` и русской строкой.

## Где искать движок и пайплайн

По порядку: `OLEG_ENGINE_DIR` / `OLEG_PIPELINE_DIR` → корень текущего
worktree → соседние `..\wt-engine`, `..\wt-pipeline` → `..\hackathon-s26-room-1`.
Первый каталог, в котором лежит `oleg_engine/` (или `oleg_pipeline/`) с
`__init__.py`, и становится рабочим; подпроцесс запускается из него с
`PYTHONPATH`, указывающим туда же.

Если движка нет, кнопка «Прогнать» показывает **одну** строку ошибки со
списком просмотренных каталогов, а не стектрейс. Таблица при этом остаётся
на месте.

## HTTP-ручки

| Метод и путь | Назначение |
|---|---|
| `GET /` | Страница. |
| `GET /api/config` | Флаги, найденные примеры, пути к движку и пайплайну. |
| `GET /api/registry?path=` | Реестр целиком (по умолчанию `out/registry.json`). |
| `POST /api/run` | `{input, mode, fresh, registry, backend, model, now}` → `{run: "<id>"}`. |
| `GET /api/run/<id>?since=N` | Новые строки лога, флаг `done`, код возврата, сводка. |
| `POST /api/run_examples` | `{examples, judge, only}` → `{run: "<id>"}`. Флаг `run_examples`. |
| `POST /api/save` | `{path, edits:[{id, owner, due, status, …}]}`. Флаг `edit`. |
| `POST /api/upload` | Multipart, поле `files` (можно несколько). |
| `GET /api/file?path=&quote=` | Текст файла + проверка цитаты на дословность. |
| `GET /api/health` | Живость и словарь `FEATURES`. |

## Что записывается на диск

Всё внутри `oleg_web/out/` (лежит в `.gitignore` этой папки):

- `out/registry.json`, `out/registry.md` — рабочий реестр;
- `out/uploads/<метка>/` — перетащенные файлы;
- `out/pipeline/` — вывод пайплайна, включая `report.md`.

При первом запуске, если рабочего реестра ещё нет, в `out/registry.json`
кладётся образец `sample/registry.json` — 8 записей, написанных руками по
`examples/01-разнородный-вход/expected.md`, с дословными цитатами из
исходных файлов. Так страница показывает осмысленные данные ещё до того,
как движок собран. Рядом лежит `sample/registry-after-02.json` — тот же
реестр после прогона примера 02 поверх (срок «Витрины» перенесён на 02.09,
«цифры по отгрузкам» закрыты); его можно открыть как `?registry=<путь к файлу>`
в адресе страницы, чтобы показать таймлайн без движка.

## Ограничения

- Прогресс — опрос раз в 500 мс, не server-sent events.
- Прогоны живут в памяти процесса: после перезапуска сервера логи прошлых
  прогонов недоступны, реестр на диске остаётся.
- Правка меняет `owner`, `due`, `status`, `what`, `due_text`, `kind`;
  добавление и удаление записей из UI не предусмотрено.
- Проверка цитаты — точное вхождение подстроки; если движок отдаст цитату
  с иными переносами строк, чем в файле, будет `✗`.
- Нет аутентификации и CSRF-защиты; не выставлять наружу.
