# Контракт инструмента — читать перед тем, как брать модуль

Скелет стоит. Труба работает от края до края. Ниже — что где лежит и какие
сигнатуры уже зафиксированы, чтобы PR не дрались.

## Запуск

```bash
python3 cli.py run --input "examples/01-разнородный-вход/input" --today 2026-08-28 --out /tmp/реестр.md
python3 cli.py check
python3 cli.py check --judge   # сверка по смыслу, нужен ANTHROPIC_API_KEY
```

**`--today` обязателен и никогда не берётся из системных часов.** Причина:
`expected.md` говорит «до пятницы **29.08**», значит опорная дата примеров —
28.08.2026. Без фиксации приёмка протухнет через сутки, и на демо мы этого не
заметим. Для примеров всегда `--today 2026-08-28`.

**Реестр по умолчанию лежит вне репозитория** (`~/.commitments/registry.json`).
Репо публичный, а реестр — это чья-то почта и рабочие чаты. Не меняйте дефолт.

## Данные — это граф

Узлы: `Source` `Chunk` `Commitment` `Person` `Event` `Topic`.

Рёбра:

```
Chunk       ──FROM──────────▶ Source
Commitment  ──EVIDENCED_BY──▶ Chunk        может быть несколько
Commitment  ──OWNED_BY──────▶ Person
Commitment  ──PREPARES──────▶ Event
Commitment  ──DERIVED_FROM──▶ Commitment
Commitment  ──SUPERSEDES────▶ Commitment
Commitment  ──ABOUT─────────▶ Topic
```

Два ребра несут ключевые проверки приёмки:

**`PREPARES`** — «забронировать зал» это задача со сроком 10.09, которая
*готовит* событие «демо» с датой 25.09. Ловушка примера 01 закрывается
структурой, а не аккуратностью промпта.

**`DERIVED_FROM`** — «подтвердить за 3 дня» производно от записи на ТО. Отмена
родителя гасит потомков через `graph.descendants(id, DERIVED_FROM)`.

`EVIDENCED_BY` намеренно множественное: одно обязательство может быть упомянуто
в письме, чате и на созвоне. Все три цитаты сохраняются — это главный аргумент
доверия на демо.

## Два идентификатора, не путать

- **`id`** — выдаётся один раз, НИКОГДА не меняется. На него будут ссылаться
  решения человека.
- **`key`** — человекочитаемый слаг для сопоставления при повторном прогоне.
  Может смениться.

Порядок операций: извлекли → **сопоставили с существующим реестром** → только
потом раздали id. Наоборот нельзя: переформулированная задача получит новый id,
и правка человека осиротеет.

## Модули и сигнатуры

| Модуль | Статус | Контракт |
|---|---|---|
| `core/` | ✅ готов | `Graph`, `save/load`, узлы и рёбра |
| `ingest/` | ✅ готов | `read_folder(path) -> (list[Source], list[Chunk])` |
| `extract/` | ✅ правила + модель за одним контрактом | `extract(chunks, known_keys, today) -> Graph` |
| `dates/` | ✅ R6EX | `resolve(commitments, today) -> list[Commitment]` |
| `registry/` | ✅ RGK8 — слияние, каскад, решения человека | `merge(base: Graph, new: Graph) -> Graph` |
| `runner/` | ✅ судья влит; без ключа откатывается на греп | `run_all(today) -> int` |

Свободных модулей нет. Открытые долги — не папки, а пункты: история переноса
срока (`SUPERSEDES`), разрез «что изменилось на этом прогоне», две корзины
«моё / рабочее». Список ведётся в `.planning/REQUIREMENTS.md`.

### `extract/` — готов, две реализации за одной сигнатурой

`extract/naive.py` — правила, работает всегда и бесплатно. `extract/llm.py` —
модель, включается флагом `--llm` при наличии ключа. Обе возвращают подграф:
обязательство плюс рёбра. `known_keys` идёт в промпт — так модель переиспользует
существующий ключ вместо изобретения нового, и дедуп решается на входе.

Оба ребра на месте в обеих реализациях: `PREPARES` (бронь ≠ демо) и
`DERIVED_FROM` («подтвердить за 3 дня» ≠ запись на ТО). Различение
`task|event|recurring` и владелец из `@упоминания` — тоже.

Строка «ТО ... запись на 21.09, подтвердить за 3 дня» намеренно даёт **два**
обязательства, а не одно. Пока напоминание сидит внутри строки родителя, отмена
гасит его молча — не потому что каскад сработал, а потому что напоминания нет
в реестре. Отдельная запись делает каскад видимым и проверяемым.

### `dates/` — готов (R6EX)

```python
def resolve(commitments: list[Commitment], today: str) -> list[Commitment]:
    """сырой текст -> Deadline (интент), не просто дата."""
```

Срок хранится структурой `Deadline`, а не плоской датой:

```python
Deadline(
    raw="до пятницы",        # как было сказано
    kind="weekday",          # hard|weekday|end_of_period|day_of_month|relative
    boundary="before",       # «до» строго раньше, «к» включительно
    anchor="2026-08-27",     # от какой даты считали
    date="2026-08-28",       # что получилось
    precision="day",         # exact|day|period|fuzzy
    alternatives=["2026-08-27 — если читать «до» строго"],
    note="ближайшая пятница после 2026-08-27",
)
```

Три причины не схлопывать в дату:

1. **«до» и «к» — разные границы.** «К понедельнику 31.08» включительно.
   «До пятницы» строго значит раньше пятницы. В деловой речи почти всегда
   имеют в виду включительно, поэтому строгое прочтение уходит
   в `alternatives`, а не выбирается молча. Спор решает заказчик.
2. **Точность разная.** «31.08» и «до конца месяца» дают одну дату, но это
   сроки разной надёжности. В выводе неточные помечены `~`, сортировка
   ставит их после точных.
3. **Пересчитать нельзя.** Если хранить только результат, при следующем
   прогоне «до пятницы» уже не пересчитаешь — интент потерян.

`c.due` остаётся как плоская проекция `deadline.date` — старый код не ломается.

Разобрать: «до 5 сентября», «до пятницы», «к понедельнику 31.08»,
«до конца месяца», «до 3 числа каждого месяца», «до десятого», «завтра утром».
Отдельный вид — `lead_time`: «за 3 дня до 21.09» считается от чужой даты,
а не от опорной, и даёт 18.09. Ветка стоит раньше разбора числовой даты,
иначе «за 3 дня до 21.09» вернуло бы само 21.09.
Неразрешимый срок оставляет запись живой с пометкой в `uncertainty`, а не
выбрасывает её.

### `registry/` — готов (RGK8), самый ценный кусок

```python
def merge(base: Graph, new: Graph) -> Graph:
    """Обновить существующее, не создать дубль. Закрыть. Отменить с каскадом."""
```

Заглушка `cli.merge_into` убрана в PR #5. Внутри четыре части:

| Файл | Что делает |
|---|---|
| `signals.py` | намерение сообщения: `cancel` / `close` / `move` — чистая функция от строки |
| `match.py` | три ступени: ключ → основы слов и общая дата → LLM-судья на спорной полосе |
| `merge.py` | два прохода: сначала обычные записи, потом сигналы поверх собранного |
| `decisions.py` | правки человека поверх всего — они сильнее входящих |

Два прохода не для красоты: сигнал «переносим на среду» должен лечь на запись,
которая могла появиться в этом же прогоне. Сигнал, не нашедший цели, не
выбрасывается — остаётся живым с пометкой «не понял, к чему относится».

Покрыто 11 тестами в `tests/test_registry.py` — без модели и без сети.

### `runner/` — судья влит, ключа нет

`runner/judge.py` сверяет по смыслу и включается флагом `--judge`. Без ключа
прогон печатает «сверка: грубая, по подстроке» и считает грепом — дата плюс
ключевое слово.

Одно исключение мимо судьи: пункт вида «записей про «Витрину» ровно одна».
Это арифметика, а не смысл — `count_check` считает строки реестра сам, в обоих
режимах одинаково. Отрицание «дублей нет» грепом непроверяемо в принципе,
и до PR с подсчётом этот пункт был вечным ложным промахом.

## Recall-first

Пропустить обязательство страшнее, чем выдумать лишнее: боль сформулирована как
«часть теряется». Сомнительное идёт в `uncertainty` и печатается в секции
«Проверь меня», а не отбрасывается молча.

**Предложение комнате:** помеченное «не уверен» не считать лишним при прогоне
приёмки. Иначе recall-first сам себе занижает счёт на демо.

## Где мы по приёмке

```
01-разнородный-вход:  8 из 8
02-повторный-прогон:  4 из 4
03-скриншот-и-отмена: 4 из 4
ИТОГО: 16 из 16
```

Счёт получен **грубой** сверкой, без ключа. Шестнадцатый пункт закрыт не
подгонкой: «новых дублей нет» заменено на «записей про «Витрину» ровно одна»,
и это считается по реестру — два вхождения дадут провал. Проверено тестом
`test_количество_считается_а_не_грепается`.

Что счёт **не** доказывает: каждый пример гоняется на свежем реестре, поэтому
хранение между прогонами приёмкой не покрыто (долг G-06). Пример 02 сливает
внутри одного прогона, а не поверх результата примера 01.

## LLM — шов готов, нужен ключ

`extract/llm.py` написан и ждёт `ANTHROPIC_API_KEY`. Без ключа конвейер молча
работает на правилах.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python3 cli.py run --input ПАПКА --today 2026-08-28 --llm
```

Это не косметика. На правилах инструмент хорошо выглядит только на `examples/`;
на реальной пачке заказчика с чужими формулировками они рассыпаются. Промпт
в `extract/llm.py` уже содержит правило про PREPARES и про переиспользование
известных ключей.

## Расхождение в приёмке — нужно слово заказчика

`expected.md` примера 01 говорит «до пятницы **29.08**», но **29.08.2026 —
суббота**. Пятница это 28.08. `dates/` считает календарно верно и даёт 28.08.
Кто прав — календарь или текст примера — решает заказчик.
