# Контракт инструмента — читать перед тем, как брать модуль

Скелет стоит. Труба работает от края до края. Ниже — что где лежит и какие
сигнатуры уже зафиксированы, чтобы PR не дрались.

## Запуск

```bash
python3 cli.py run --input "examples/01-разнородный-вход/input" --today 2026-08-28 --out /tmp/реестр.md
python3 cli.py check
```

**`--today` обязателен и никогда не берётся из системных часов.** Причина:
`expected.md` говорит «до пятницы **29.08**», значит опорная дата примеров —
28.08.2026. Без фиксации приёмка протухнет через сутки, и на демо мы этого не
заметим. Для примеров всегда `--today 2026-08-28`.

**Реестр по умолчанию лежит вне репозитория** (`~/.commitments/registry.json`).
Репо публичный, а реестр — это чья-то почта и рабочие чаты. Не меняйте дефолт.

## Данные — это граф

Узлы: `Source` `Chunk` `Commitment` `Person` `Event` `Topic`.

Рёбра:

```
Chunk       ──FROM──────────▶ Source
Commitment  ──EVIDENCED_BY──▶ Chunk        может быть несколько
Commitment  ──OWNED_BY──────▶ Person
Commitment  ──PREPARES──────▶ Event
Commitment  ──DERIVED_FROM──▶ Commitment
Commitment  ──SUPERSEDES────▶ Commitment
Commitment  ──ABOUT─────────▶ Topic
```

Два ребра несут ключевые проверки приёмки:

**`PREPARES`** — «забронировать зал» это задача со сроком 10.09, которая
*готовит* событие «демо» с датой 25.09. Ловушка примера 01 закрывается
структурой, а не аккуратностью промпта.

**`DERIVED_FROM`** — «подтвердить за 3 дня» производно от записи на ТО. Отмена
родителя гасит потомков через `graph.descendants(id, DERIVED_FROM)`.

`EVIDENCED_BY` намеренно множественное: одно обязательство может быть упомянуто
в письме, чате и на созвоне. Все три цитаты сохраняются — это главный аргумент
доверия на демо.

## Два идентификатора, не путать

- **`id`** — выдаётся один раз, НИКОГДА не меняется. На него будут ссылаться
  решения человека.
- **`key`** — человекочитаемый слаг для сопоставления при повторном прогоне.
  Может смениться.

Порядок операций: извлекли → **сопоставили с существующим реестром** → только
потом раздали id. Наоборот нельзя: переформулированная задача получит новый id,
и правка человека осиротеет.

## Модули и сигнатуры

| Модуль | Статус | Контракт |
|---|---|---|
| `core/` | ✅ готов | `Graph`, `save/load`, узлы и рёбра |
| `ingest/` | ✅ готов | `read_folder(path) -> (list[Source], list[Chunk])` |
| `extract/` | 🟡 R6EX — правила + шов под модель | `extract(chunks, known_keys, today) -> Graph` |
| `dates/` | ✅ R6EX | `resolve(commitments, today) -> list[Commitment]` |
| `registry/` | ⬜ **СВОБОДЕН — берите** | `merge(base: Graph, new: Graph) -> Graph` |
| `runner/` | 🟡 грубый, ждёт LLM-судью | `run_all(today) -> int` |

### `extract/` — фаза 2

Сейчас правила без модели. Заменить тело на вызов LLM, **сигнатуру не менять**.
Возвращает подграф: обязательство плюс рёбра. `known_keys` идёт в промпт — так
модель переиспользует существующий ключ вместо изобретения нового, и дедуп
решается на входе.

Что должно появиться: рёбра `PREPARES` и `DERIVED_FROM`, различение
`task|event|recurring`, владелец из контекста.

### `runner/` — фаза 2

Сверка сейчас грубая: дата плюс ключевое слово. По правилам комнаты сверять надо
**по смыслу** — нужен LLM-судья. До него счёт занижен, и это честно.

## Recall-first

Пропустить обязательство страшнее, чем выдумать лишнее: боль сформулирована как
«часть теряется». Сомнительное идёт в `uncertainty` и печатается в секции
«Проверь меня», а не отбрасывается молча.

**Предложение комнате:** помеченное «не уверен» не считать лишним при прогоне
приёмки. Иначе recall-first сам себе занижает счёт на демо.

## Где мы по приёмке

```
01-разнородный-вход:  8 из 8
02-повторный-прогон:  3 из 4
03-скриншот-и-отмена: 4 из 4
ИТОГО: 15 из 16
```

Единственный промах — «новых дублей ни по одному пункту нет». Это `registry/`.

## LLM — шов готов, нужен ключ

`extract/llm.py` написан и ждёт `ANTHROPIC_API_KEY`. Без ключа конвейер молча
работает на правилах.

```bash
export ANTHROPIC_API_KEY=sk-ant-...
python3 cli.py run --input ПАПКА --today 2026-08-28 --llm
```

Это не косметика. На правилах инструмент хорошо выглядит только на `examples/`;
на реальной пачке заказчика с чужими формулировками они рассыпаются. Промпт
в `extract/llm.py` уже содержит правило про PREPARES и про переиспользование
известных ключей.

## Расхождение в приёмке — нужно слово заказчика

`expected.md` примера 01 говорит «до пятницы **29.08**», но **29.08.2026 —
суббота**. Пятница это 28.08. `dates/` считает календарно верно и даёт 28.08.
Кто прав — календарь или текст примера — решает заказчик.
